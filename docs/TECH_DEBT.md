# Technical debt register

Visible on purpose. Each item says what the shortcut is, why it was taken, and how to pay it down.

**Row numbers are permanent identifiers.** ADRs, code comments and tests cite them (`#25`, `#30`,
`#33`, `#38`, `#40`, `#42` today), so a paid-down row is struck through in place and its number is
never reused. Every row was re-checked against the code on 2026-09-19.

**Start here** — the open rows a reader is most likely to act on, in the order they bite:

1. **#30 and #2 — the eagerly loaded bundle is 432.76 KB gzip against a 440 KB ceiling.** The next
   phase has about 7.2 KB to spend, or has to restate the budget with its own measurement.
2. **#19 and #20 — the deployed studio's authentication and its account.** Access needs a hostname
   in a zone; the account is described three different ways across the docs (`docs/PRIORITIES.md`).
3. **#43 — five block types cannot be converted to code**, including the two-column row in the
   shipped `Product launch` starter, so the first conversion most people try is refused.
4. **#26 — the Node runtime loses every template on restart**, and since phase 7b the studio looks
   as if it saved them.
5. **#24 and #28 — the D1 store is proven on local D1 only.** Both wait on somebody else: a Vitest 5
   workers pool, and remote Cloudflare credentials.
